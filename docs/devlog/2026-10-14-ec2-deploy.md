# 2026-10-14 EC2 서버에 배포

## 목표

- 노트북에서 띄운 `docker compose up`을 실제 서버에서 실행
- 인터넷 주소로 누구나 코스콕에 접속 가능하게

## 전체 흐름

```
1. AWS 가입, EC2 인스턴스 생성        ← 서버 빌리기
2. SSH로 서버 접속
3. 서버에 Docker 설치
4. 코드(git clone) + 빌드 결과물(scp) 올리기
5. docker compose up → http://<서버IP> 접속
```

## 1. EC2 인스턴스

| 항목     | 선택                          | 이유                                                                   |
| -------- | ----------------------------- | ---------------------------------------------------------------------- |
| 리전     | 시드니 (ap-southeast-2)       | 무료 플랜은 계정에 배정된 리전만 사용 가능. 서울은 유료 플랜 전환 필요 |
| OS       | Ubuntu Server 24.04 LTS (x86) | 26.04보다 자료가 많음. 둘 다 LTS                                       |
| 유형     | t3.small (2GB)                | Spring + MySQL + Nginx를 한 대에서. 1GB(t3.micro)는 스왑 필요          |
| 키 페어  | RSA, .pem                     | 비밀번호 대신 열쇠 파일로 접속. 한 번만 다운로드됨                     |
| 스토리지 | 20GB gp3                      | 기본 8GB는 Docker 이미지 몇 개면 부족                                  |

### 보안 그룹 (서버 방화벽)

| 포트       | 소스      | 이유                                                 |
| ---------- | --------- | ---------------------------------------------------- |
| 22 (SSH)   | 내 IP     | 서버 접속은 나만                                     |
| 80 (HTTP)  | 0.0.0.0/0 | 누구나 서비스 접속                                   |
| 3307, 8080 | 열지 않음 | DB, 백엔드는 밖에서 직접 접근 불가. Nginx(80)만 공개 |

### 비용 (무료 플랜)

- 크레딧에서 차감: 실행 시간, 스토리지, 공인 IP
- 안 쓸 때는 인스턴스 중지(Stop). 다시 켜면 공인 IP가 바뀔 수 있음
- 크레딧 소진이나 6개월 후 계정 종료. 플랜 업그레이드 전엔 카드 결제 없음

## 2. SSH 접속

```
icacls $env:USERPROFILE\.ssh\coursekok-key.pem /inheritance:r
icacls $env:USERPROFILE\.ssh\coursekok-key.pem /grant:r "$($env:USERNAME):(R)"
ssh -i $env:USERPROFILE\.ssh\coursekok-key.pem ubuntu@<서버IP>
```

- 키 파일은 나만 읽을 수 있어야 SSH가 사용 (권한이 열려 있으면 거부)
- Ubuntu 이미지 기본 사용자는 `ubuntu`
- 프롬프트가 `ubuntu@ip-...:~$`면 서버 안. 명령이 서버에서 실행됨
- `ip-172-31-...`은 AWS 내부용 사설 IP. 외부 접속은 공인 IP

## 3. Docker 설치

```
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ubuntu
exit   # 그룹 변경은 재접속해야 적용
```

- 공식 설치 스크립트로 Docker와 Compose 설치
- docker 그룹에 추가해 `sudo` 없이 사용

### (t3.micro일 때) 스왑 2GB

```
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

- 메모리가 모자랄 때 디스크를 메모리처럼 사용. 없으면 OOM으로 컨테이너가 강제 종료될 수 있음

## 4. 코드와 빌드 결과물 올리기

| 필요한 것                            | GitHub에 있나     | 방법        |
| ------------------------------------ | ----------------- | ----------- |
| compose, Dockerfile, nginx.conf, SQL | 있음              | `git clone` |
| 백엔드 jar                           | 없음 (.gitignore) | `scp`       |
| 프론트 dist                          | 없음 (.gitignore) | `scp`       |
| `.env`                               | 없음 (.gitignore) | `scp`       |

서버:

```
git clone https://github.com/oz115/coursekok-v2.git
cd coursekok-v2
mkdir -p backend/CourseKok/target
```

노트북:

```
$KEY = "$env:USERPROFILE\.ssh\coursekok-key.pem"
$SERVER = "ubuntu@<서버IP>"
scp -i $KEY backend\CourseKok\target\CourseKok-0.0.1-SNAPSHOT.jar "${SERVER}:~/coursekok-v2/backend/CourseKok/target/"
scp -i $KEY -r frontend\dist "${SERVER}:~/coursekok-v2/frontend/"
scp -i $KEY .env "${SERVER}:~/coursekok-v2/"
```

- `scp`: SSH와 같은 열쇠로 파일 복사. `-r`은 폴더째

## 5. 실행

```
cd ~/coursekok-v2
docker compose up -d --build
docker compose ps
```

- 노트북과 같은 명령. Docker 덕분에 서버 환경(Java 없음)과 상관없이 동일하게 동작
- 카카오 지도: 개발자 콘솔 > 플랫폼 > Web 사이트 도메인에 서버 주소 등록 필요

## 트러블슈팅

### 리전이 시드니로 생성됨

- 무료 플랜 계정은 배정된 리전(시드니)만 사용 가능. 서울 전환 시도 중 기존 인스턴스를 종료해 재생성
- 키 페어와 보안 그룹은 인스턴스와 별개로 리전에 남아 있어 재사용
- 배운 점: 리전 제약을 확인한 다음에 리소스를 지울 것

### SSH `Connection timed out`

- `Test-NetConnection <서버IP> -Port 22` → `TcpTestSucceeded : False`
- 원인: 접속한 공용 와이파이가 22번 포트 아웃바운드를 차단
- 해결: 휴대폰 핫스팟으로 전환 + 보안 그룹 SSH 소스를 새 "내 IP"로 수정
- 배운 점: timeout은 열쇠 문제가 아니라 경로 차단. 내 쪽 네트워크와 서버 방화벽을 나눠서 확인

### scp 사용법만 출력됨

- 원인: 붙여넣기 중 줄바꿈이 들어가 명령이 두 개로 실행. 받을 곳(target)이 빠짐
- 배운 점: `usage:` 출력은 인자가 부족하다는 뜻
